# Population-Level Bootstrap Evaluation — Design Plan

> Design specification, to run once the 100-subject dataset finishes processing. Modeled directly on the statistical rigor standard in **Misra & Pessoa (2025, *eLife*), "Human brain dynamics and spatiotemporal trajectories during threat processing"** — Joyneel's SLDS/threat-processing paper, shared for exactly this purpose. Not a loose inspiration: the design below reuses that paper's specific mechanics where they transfer, and calls out where our setting is easier (cheap retraining) or harder (block-design leak-safety) than theirs.

## 1. What the reference paper actually does (read directly from the Methods, not summarized from memory)

- **Held-out hyperparameter-selection set, separate from reported results**: 30 participants used only to pick K (number of SLDS states) and D (latent dimensionality); the headline results come from a *different* 92 participants. This prevents the classic double-dipping bias of tuning and reporting on the same data.
- **Bootstrap over participants, not over data points**: 500 bootstrap samples generated by resampling *participants* with replacement; a full SLDS model is refit on every single resample.
- **Empirical stopping rule, not an arbitrary round number**: bootstrap samples were generated in batches of 100, and the procedure stopped once parameter estimates (state centroids) stopped changing beyond 1e-5 precision — 500 wasn't picked in advance, it was where the estimates happened to stabilize.
- **Structure-preserving null distributions**: significance testing used permutation-based surrogates that shuffled *contiguous blocks* (whole states, or whole condition segments) rather than individual timepoints, preserving the data's real temporal/block structure under the null — directly analogous to why our own forecasting work enforces leak-safety within condition blocks (`data_setup.build_forecast_window_index`).
- **Nonparametric significance testing + multiple-comparison correction**: Wilcoxon signed-rank tests on bootstrap distributions vs. null distributions, Bonferroni-corrected throughout.

## 2. What transfers directly to NeuroLens-RAG, and what's actually easier for us

**Easier for us**: an SLDS fit is expensive enough that refitting 500 times only makes sense because the paper's compute budget allowed it. Our GRU/Transformer models train in **seconds** (the entire 4-experiment ladder finishes in well under a minute — see `05_train_eval_compare.ipynb`). This means we can afford the *more* rigorous version of their approach — a full retrain per bootstrap resample — rather than the cheaper shortcut (bootstrap only the evaluation, keeping one fixed trained model). Do the expensive-but-correct thing since we can actually afford it here.

**Harder for us**: their bootstrap resamples participants for a task with continuous, non-block-structured stimuli (moving circles). Ours is block-designed (MOTOR task), which is exactly why `build_forecast_window_index`'s leak-safety check exists — any population-level resampling scheme here must keep whole *subjects* together (never split a subject's windows across a bootstrap sample vs. its complement), for the same underlying reason overlapping windows can't be split across train/val/test at the individual-window level (§14 of `project-handoff-summary.md`).

## 3. Concrete design for the 100-subject dataset

### 3.1 Held-out hyperparameter-selection subjects

Before touching final numbers: carve out a small fixed subject subset (e.g. 10 of the 100) reserved *only* for any future hyperparameter decisions (architecture choice, `lambda_hrf`, window size, etc.) — mirroring the paper's 30-participant hyperparameter set. **We have not been doing this so far** — the 20-subject hyperparameter sweep (`07_hyperparameter_sweep.ipynb`) used the same val/test subjects that the headline Case 1 results are reported on, which is a real, worth-naming gap relative to this standard. Fixing it going forward: reserve a hyperparameter-selection subset from the 100, and never report headline numbers on it.

### 3.2 Main split

Remaining 90 subjects, split subject-level (e.g. ~65/15/10, roughly preserving the 70/15/15-ish ratio used at 20-subject scale, adjusted since 10 are carved out for hyperparameter selection).

### 3.3 Bootstrap procedure (the core of "population-level error bars")

For a chosen metric (e.g. Case 1 test macro-F1, Case 2 test macro-F1, a TCAV score, a forecasting R²):

1. Generate bootstrap resamples of **training + test subjects together** (whole-subject resampling, with replacement), following the paper's "resample participants" principle — not resampling windows, which would break subject-level independence exactly the way a naive window-level split would.
2. Retrain the model from scratch on each resampled training set (affordable — see §2), and evaluate on the correspondingly resampled test set.
3. Use the paper's **empirical stopping rule**, not a fixed number picked in advance: generate resamples in batches (e.g. 50 at a time), track a running estimate of the metric's mean and its precision (e.g. the width of the bootstrap confidence interval), and stop once that width stabilizes rather than committing to "500" before seeing the data. Given our models are cheap, this could plausibly run to several hundred resamples within a reasonable wall-clock budget — but let the stability criterion decide, not a copied number.
4. Report the metric as **mean ± bootstrap CI (e.g. 2.5th/97.5th percentile)** across resamples, not a single point estimate — this is the actual deliverable this whole design exists to produce.

### 3.4 Null / significance testing (where relevant)

For comparisons that need a p-value (e.g. "is Transformer significantly better than GRU," "is the auxiliary HRF loss's effect significant") — use the paired-bootstrap-distributions approach the paper uses (Wilcoxon signed-rank on paired bootstrap estimates) rather than a single-sample t-test, since it naturally accounts for the same resampling variability used everywhere else in this design. Apply Bonferroni correction across whatever family of comparisons is being tested at once (e.g. the 4-experiment ladder has 6 pairwise comparisons).

## 4. What this design plan does *not* yet cover (explicitly out of scope for this doc)

- Which metrics to prioritize for bootstrapping first (macro-F1 is the obvious first candidate, matching what's already reported everywhere else in this project).
- Whether to bootstrap Case 2 and Case 3 the same way once they exist at 100-subject scale, or treat this as Case-1-first.
- Compute/wall-clock budget for the stopping-rule-driven bootstrap loop — needs an actual pilot run once the 100-subject data exists, not a guess now.

## 5. Results — **done** (100-subject scale)

Implemented in [`12_population_level_evaluation.ipynb`](../notebooks/12_population_level_evaluation.ipynb). One deviation from §3.3's plan, made explicit rather than silently substituted: **repeated random splits, not literal with-replacement bootstrap over subjects**. `data_setup.py`'s window index is keyed by unique `(subject, run)` pairs, so a subject drawn twice in a with-replacement sample wouldn't actually contribute its windows twice — the infrastructure de-duplicates by construction. Repeated re-partitioning (Monte Carlo cross-validation) is a legitimate, simpler alternative that works with the existing infrastructure as-is; proper weighted resampling would need real code changes, not attempted here.

**The empirical stopping rule worked as intended**: only 20 repeats were needed before the 95% CI half-width stabilized, well under the 100-repeat cap (~8 minutes total wall-clock, given each retrain takes ~24s at this data scale) — a genuinely useful outcome of using a stability criterion instead of guessing a count upfront.

**Headline population-level result**: mean test macro-F1 = **0.920**, 95% CI = **[0.909, 0.934]** across 20 repeated random 65/13/12 splits (std = 0.007, range 0.908–0.936). This properly generalizes the earlier single-split 20-subject result (0.925) — **Case 1's decoding accuracy is ~92% ± ~1.3 points at the population level, not a lucky single split.**

**Complementary post-hoc bootstrap** (2000 resamples of test-subject composition, one fixed model, no retraining): mean = 0.926, 95% CI = **[0.909, 0.942]** — a *wider* interval than the repeated-splits analysis, despite using one fixed model rather than 20 independently retrained ones. **Worth explaining, not just reporting**: this doesn't mean the model is less reliable than the repeated-splits result suggests. With only 12 test subjects, with-replacement resampling from such a small discrete pool has inherently high sampling variance (a single resample can easily lose 2–3 of the 12 subjects entirely, or triple-count one) — this inflates the bootstrap CI independent of model quality. Misra & Pessoa's paper bootstrapped 92 participants, not 12; a much larger pool damps exactly this effect. The repeated-splits analysis, which draws from the full 90-subject pool each time, is the more trustworthy of the two population-level estimates at this subject count — the post-hoc bootstrap is more a statement about the granularity limit of a 12-subject test set than about the model.

**Still not done, flagged in §4 as future work**: bootstrapping Case 2/3 the same way; proper weighted (true bootstrap) resampling if the closer match to the reference paper's exact mechanics is ever wanted; the held-out hyperparameter-selection subset (`MOTOR_HYPERPARAM_SUBJECTS`) was correctly *reserved* but not yet actually used for any real hyperparameter decision, since the sweep in `07_hyperparameter_sweep.ipynb` predates the 100-subject split.

## 6. Statistical treatment for TCAV scores (concept-level, not accuracy-level)

Extends §3 to Concept Activation Vectors specifically, since a TCAV score has its own significance-testing question ("is this concept direction meaningful, or would nearly anything score this way") that accuracy metrics don't.

**Bootstrap CI — the cheap version, in place now.** Same subject-level resampling principle as §3.3, applied to a fixed trained model and a fixed, already-derived concept direction: resample the test set's subject composition with replacement, recompute the mean TCAV on each resample, report the 2.5th/97.5th percentile. This only captures test-sampling variability — the direction itself is treated as fixed. This is the *complete* picture only for a direction with no fitting step to resample in the first place (e.g. a pure text-arithmetic direction pulled back through a linear projection, which falls straight out of the trained model and a phrase, deterministically). Case 2's standardized derivation (the fitted post-hoc classifier head, `docs/interview-prep-neurolens-rag.md` §11.3 standardization note) does have a fitting step — a labeled-example logistic-regression probe, same as Case 1/3 — so for Case 2 as now used, the direction-fitting resampling gap below applies exactly as it does for Case 1/3, not as an exception.

**Not yet done: resampling the direction-fitting data too.** For Case 1's labeled-example probe (`train_cav`, logistic regression on brain examples), a fully rigorous bootstrap would also resample the *training* subjects used to fit the probe and refit `v_C` on each resample, propagating direction-estimation uncertainty into the final CI, not just evaluation-sampling uncertainty. Flagged here explicitly as future work, not silently skipped — matches §4/§5's existing pattern of naming what's deferred rather than letting the gap go undocumented. Likely affordable given how cheap Case 1's probe fit is (a single `LogisticRegression.fit()` call, not a retrain), but not yet implemented or measured.

**What a TCAV null should actually test.** An early attempt used a null distribution of TCAV scores from directions drawn uniformly at random in the model's 128-dim hidden space, on the reasoning that a meaningless direction should score near 0.5. It didn't work: the null distribution came back with mean 0.56 and std 0.33, spanning nearly the full [0,1] range — almost *any* fixed direction produces a near-extreme TCAV score for a given class in this representation, because gradients for individual examples of one class are apparently similar enough to each other (low angular spread) that a random direction's sign-agreement with them is dominated by which side of one effective mean-gradient hyperplane it happens to fall on, not by anything about the direction's semantic content. A "structure-preserving" null (random splits of the 6 known classes into nonsense positive/negative groups, built the same way real concept directions are) was better-centered (mean 0.49) but still didn't cleanly separate a real, validated concept from noise, likely because many random splits still partially overlap with genuine class structure by combinatorics alone.

**The test that actually works: fix the direction, permute which class it's evaluated against.** Rather than asking "is this direction unusual among all directions" (poorly behaved here, per above), ask "does this direction specifically single out its intended class, compared to the other classes, more consistently than chance." Concretely: hold the concept direction fixed, compute its TCAV score against *every* class's held-out examples (not just the target), and check whether the intended target class ranks highest — repeated across subject-level bootstrap resamples for a robust probability rather than one point estimate. Real result for a phrase deliberately avoiding every closed-vocabulary keyword ("gustatory motor articulation activates a distinct cortical zone", tested against the `tongue` class, direction derived via the text-arithmetic pullback method since superseded as Case 2's default — `docs/interview-prep-neurolens-rag.md` §11.3 standardization note): TCAV = 0.685, 95% CI [0.646, 0.725] across 1000 subject-resampled bootstraps, and **tongue ranked #1 of 6 classes in every single resample (P = 1.000)**. This is now the recommended significance-testing design for TCAV going forward — cheap (reuses already-extracted pooled features, no retraining), avoids the high-dimensional-random-direction pitfall entirely, and gives a clean, interpretable statement ("this concept specifically implicates class X, robustly across resampling") rather than a p-value against a poorly-understood null.

**A ceiling case, found applying this to Case 3 (`src/neurolens/concepts.py::cross_class_rank_bootstrap_test`, `notebooks/17_case3_brain_hrf_coembedding.ipynb`).** TCAV's raw score is binarized (fraction of examples with positive directional derivative), so it saturates at exactly 1.0 whenever a representation is highly separable for a given class — and when *several* classes saturate at 1.0 simultaneously under the same direction (which happened for every one of Case 3's 5 concepts, whose probe accuracy was 0.989–0.993), "does the target rank #1" becomes a tie among the saturated classes. The first implementation broke ties via Python's `max()`, which silently keeps the *lowest-index* class among equal values — not a random or principled choice — so P(rank1) came back near 0 for several concepts against their own true target class, looking exactly like a null result when it was actually a tie-breaking artifact unrelated to the direction's meaning. **Caught before being written up as a finding**, by noticing the pattern only tracked class index rather than which class the phrase/concept was about. Fixed by breaking ties uniformly at random and reporting `frac_ties_at_max` alongside `p_rank1`; after the fix, tied concepts correctly return P(rank1) ≈ 1/(number of classes tied at the ceiling) (e.g. ~0.50 for a 2-way tie, ~0.25 for a 4-way tie) rather than a spuriously low or high number. **Lesson for future use of this test**: when `frac_ties_at_max` is high, P(rank1) alone cannot distinguish "the concept doesn't specifically implicate its target" from "the representation is so separable that TCAV's binarized score has no room left to discriminate between classes" — the two look identical under this test. A continuous, magnitude-based variant (mean signed directional derivative rather than just its sign) would very likely recover discriminating power in this regime; not yet built, noted as follow-up work.
